1 · A program says what it can touch

the languagecancho authority

“Before I run anything: what can this program reach?”

The compiler derives, from the source alone, what a program may do to the world, and prints it. The first program only writes to standard output. The second opens one file under /tmp, and says so. Neither can reach the network: the capability to do so was never handed to main, so there is nothing to reach with.

a real run
$ cancho authority hello.cho --std
performs
    io_write
never touches
    the filesystem
    the network
    the heap
    the command line
    signals
    other programs
    foreign code
a real run
$ cancho authority fixed.cho --std
performs
    fs_read("/tmp")
    io_write
never touches
    the network
    the heap
    the command line
    signals
    other programs
    foreign code
Reading it. The first program performs io_write and “never touches the filesystem, the network, the heap”. The second adds fs_read("/tmp") and nothing else. These are statements about every possible run of the program, not about a test run, and the compiler is the one that makes them.

2 · The compiler says no

the languagecancho check

“I opened a file and forgot to close it. Does it matter?”

A resource that is opened has to be consumed. The program below opens a file and never closes it; the compiler does not warn, it refuses, and it names the value and the line.

a real run
$ cancho check leak.cho --std
exit 1
leak.cho:12:9: error: `f` is still live at the end of this block; nothing consumes it
            match open_read(c, "/tmp/notes.txt") {
            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
Reading it. The error is about a value, f, that is still live at the end of its block. Fixing it is one line (file_close(f)), and the fixed program is the one whose authority you read in story 1. Everything below is built from programs that compile under rules like this one.

3 · Three tools, three authorities

the toolstablestatsml

“I am going to feed my data to three command-line tools. What may each of them do with it?”

The three tools are written in cancho, so each one has an authority row, derived by the compiler and committed in its repository (manifests/*.authority.json); CI fails if the built program differs from it. Here they are side by side.

Reading it. None of the three can open a network connection, call foreign code or read a clock. table may read standard input and use threads; stats needs neither; only ml may write files (the model it fits). The rows are the committed manifests, read when this page was recorded; their SHA-256 begin 9df864cd29 (table), 3828120c5c (stats) and 0b66a7d07b (ml).

4 · One logger, three tools

the pipelinetablestatsml

“The logger in the hut writes a reading every five minutes, as JSON lines. Is it colder at night? And can a model tell me tomorrow’s temperatures?” — the keeper of a mountain hut

Five days of readings, 1,440 lines (demo/stories/logger.jsonl). First table turns them into one row per hour, with the mean computed from exact decimals; its CSV is the input of the other two. stats compares the day hours with the night hours; ml learns the daily cycle from the first four days and predicts the fifth.

a real run
$ table --input-format jsonl --fields day,hour,period,temp_c --group day,hour,period \
    --agg count,mean:temp_c:dec(2)@4 --sort day --format csv > hourly.csv
day,hour,period,count,mean:temp_c

d1,1,night,12,8.9042
d1,10,day,12,16.4350
d1,11,day,12,18.1508
...  (120 rows)
a real run
$ stats ci diff --cols mean:temp_c --group period hourly.csv
{
  "levels": {"a": "day", "b": "night"},

a real run
$ ml fit --model forest --task ... forest.ml train.csv

Reading it. The day hours are 6.53 °C warmer than the night hours on average, with a 95% interval from 5.54 to 7.52 (test t2 says p = 1.0e-24). On the fifth day, which the model never saw, the forest is wrong by 0.998 °C (root mean square) where the mean of the other days is wrong by 4.29: it learnt the daily cycle. Three programs, three authorities, one CSV between them.

5 · The same bytes, in any order

determinismtablestatsml

“I merged two loggers’ files and the lines are in another order. Will the answers change?”

The whole pipeline of story 4 again, three times: the logger’s lines in the order they were written, shuffled, and reversed. For each run, the SHA-256 of the hourly CSV, of the statistics document and of the fitted model file:

Reading it. Nine digests, three distinct values, each repeated three times: the order of the lines changes nothing. The means are exact decimals, so adding them in another order cannot change a digit; the groups come out sorted by key; the forest’s trees draw from streams derived from a seed. (A bootstrap, by design, is a function of the file’s bytes and its seed: row order does matter there, and the answer says so.)

6 · Did the campaign work, and can finance check it?

marketingtablestats

“Finance counts buyers from the purchase ledger, the growth team counts them from the experiment tool. Do they agree, and is the lift real?” — the analyst who has to sign the report

Two sources, one question. table joins the shop’s purchases to the arm of each user, leaves out what was bought before the campaign started (a --where on the date), and counts distinct buyers and the exact revenue per arm. The experiment tool’s export has one row per user with a 0 or 1; table adds that column up. If the two ledgers differ by one buyer, the report does not go out.

a real run
$ table --join arms.csv --on user_id --where date:date >= 2026-09-01 --group arm --agg \
    count,distinct:user_id,sum:amount:dec(2) --sort arm --format csv purchases.csv
arm,count,distinct:user_id,sum:amount
ads,285,250,13812.61
holdout,228,196,11682.33
a real run
$ table --group arm --agg count,sum:bought --sort arm --format csv users.csv
arm,count,sum:bought
ads,4000,250
holdout,4000,196

They agree, arm by arm. Now the experiment itself, with the export as input: the difference in conversion between the arm shown the ad and the held-out arm, with its interval (the Newcombe one, for a difference of two proportions), and the test.

a real run
$ stats ci prop --cols bought --success 1 --group arm users.csv
{
  "estimate": 0.0135,
  "interval": {
    "method": "newcombe",
    "low": 0.0034427799706339673,
    "high": 0.02360737411150906
  }
}
a real run
$ stats test prop --cols bought --success 1 --group arm users.csv
{
  "statistic": 2.631375542038577,
  "p_value": 0.008504000827229921,
  "p_method": "normal"
}

And for the file that goes to finance: the SHA-256 of the exact totals and of the statistics document, with the purchases in the order exported, shuffled, and reversed (with the users reversed as well):

Reading it. Both counts of buyers agree: 250 in the arm shown the ad and 196 in the held-out arm. The ad adds 1.4 points of conversion (95% interval 0.34 to 2.4, p = 0.0085). Six digests, two distinct values, each repeated three times: another order of the same rows is the same report, byte for byte. The cancho-stats page goes on to revenue, to the dashboard that overstates the lift, and to a regional experiment; cancho-ml to who the ad moves.

7 · More fields

go further

Each of the three tools has its own page of stories, in increasing complexity, with a figure for each and a section from biology and medicine, chemistry, physics, the social sciences, marketing and finance. Every number on them is drawn from a real run, like the ones above.

Biology

  • Six mice against six: exact rank and permutation tests (stats)
  • A growth plate: exact means of replicates (table)
  • Tumour or normal?: which genes matter (ml)

Chemistry

  • Two methods, one sample set: correlation is not agreement (stats)
  • Burette readings: a declared precision (table)
  • A calibration curve: fit once, apply to unknowns (ml)

Physics

  • Same source, two detectors: a shape the means cannot see (stats)
  • Two days of a logger: JSON lines by the hour (table)
  • Two kinds of pulse: clusters with no labels (ml)

Medicine

  • Did the drug lower the blood pressure?: a randomized trial, Holm over three endpoints (stats)
  • No serious events: how safe is that?: an exact interval for zero (stats)
  • Which lots are out of specification?: batch records in exact decimals (table)
  • Who will come back within 30 days?: a risk score and its threshold (ml)

Marketing

  • Did the ads cause the sales?: a randomized holdout (stats)
  • The dashboard that was too good to be true: selection bias (stats)
  • From the raw tables to the holdout analysis: join, window, per-arm totals (table)
  • Who does the ad actually move?: uplift on a randomized test (ml)

Finance

  • How bad is a bad day?: heavy tails, a bootstrapped quantile (stats)
  • Six backtests, one winner: counting what was tried (stats)
  • Month end, to the cent: totals that must add up (table)
  • Whom should the bank lend to?: a default score and a cutoff with a price (ml)

Social science

  • What does the town think?: intervals for a share, ordinal tests (stats)
  • Who answered twice?: counts and duplicates (table)
  • Who supports the tram line?: a model to read (ml)
