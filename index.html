Trust without comprehension

Pre-1.0 · alpha products are built with it

Tools built for agents.
Not adapted from humans.

cancho is a programming language and toolchain for software built by AI agents and checked by machines. Programs declare what they can do, dependencies have stable identities, and the compiler returns structured evidence that other tools can read and check.

The bet: you should not have to read what an agent wrote to trust it.

Identity, not lines

A canonical AST gives every declaration a stable hash, and dependencies pin to hashes, not version strings. Nothing changes under you because a maintainer published a new version.

Authority, not trust

What a program may do is in its type, so a reviewer checks the policy, not every line. cancho authority names what is reachable, and says “unbounded” when it can’t.

Verified, not read

The compiler answers in data: a rule tag, a position, a fix. Diagnostics, the command tree and a skill file come out of the binary for an agent to use directly.

Trust without comprehension

An agent writes. Five links check it.

Comprehension is one basis for trust; verification is another, and it is the one that scales. Nothing in this chain asks a person to read the code first. Each link is checked, and none of them has to be understood.

The same map as a list
  • cancho · page (built): The language and its Rust compiler. A second compiler, written in cancho, is being checked against it.
  • cancho-ui · page (built): A UI language whose compiler knows what each component is allowed to do. Builds JavaScript and DOM.
  • cancho-hooks · page (alpha): Webhook delivery: on disk before the 202, signed, retried, dead-lettered and replayable.
  • cancho-cache · page (alpha): Redis-compatible string cache over RESP2/RESP3, expiry and LRU in a fixed arena.
  • cancho-gateway · page (design): An auditable HTTP/1.1 reverse proxy: a fixed upstream set proven by the authority report.
  • cancho-mqtt · page (design): An MQTT 3.1.1 broker: one thread, one poller, bounded memory.
  • cancho-dns · page (design): A forwarding and caching DNS resolver: bounded parser, fixed arena.
  • cancho-oci (design): Container images without a daemon: a deterministic OCI image builder and registry client.
  • cancho-pg (early): PostgreSQL client: v3 protocol, SCRAM-SHA-256, extended queries, TLS, non-blocking pool.
  • cancho-schema (early): Schemas as data: validation, problem+json errors and JSON Schema 2020-12 from one value.
  • cancho-web · page (early): Typed routes, validated bodies, problem+json errors and an OpenAPI document from one declaration.
  • cancho-log (early): A durable, segmented, append-only log with crash-safe recovery that cuts off a torn tail.
  • cancho-stats · page (design): Statistics on tabular data as a command line an agent can read: exact sums, tests, intervals, resampling.
  • cancho-ml · page (design): Classical ML, pipelines and evaluation: deterministic, bounded, agent-first.
  • cancho-tools · page (working): Nine small tools for agents: seek, list, peek, jsonq, tally, hash, write, replace, move. JSON out, errors that name a rule.
  • cancho-table · page (built): Select, filter, group and aggregate CSV/TSV for agents; bounded, exact, byte-stable.
  • cancho-robot · page (design): A robot arm controller: the Feetech servo bus, SO-101 kinematics and a safety core every motion goes through.
  • cancho-gpu · page (built): A compiler for lex-gpu's .lx tile kernels to CUDA C and Metal, written in cancho.
  • cancho-code · page (built): An AI coding assistant that proves its work: the cancho compiler checks every piece the model writes, and a task is done only when the compiler and the task's own examples say so.
  • cancho-forge · page (built): An agent-run software company you can audit: state, budgets, approvals and evidence are kept by the runtime, and a worker cannot accept its own work.
  • cancho-hdl · page (built): One .chw file declares the software/hardware boundary (registers, fields, interrupts, DMA); it is checked, and a C header, device tree, SystemVerilog RTL and CMSIS-SVD are generated from it.
  • cancho-client-gen (built): Reads the OpenAPI 3.1 document that cancho-web generates and writes strictly typed clients; the contract, both ways.
  • cancho-fetch (design): An agent-safe fetch: HTTP and HTTPS to a fixed, built-in list of hosts, with the list in the binary's authority row instead of a flag.
  • cancho-mqtt-client (design): An MQTT 3.1.1 client library: connect, publish, subscribe, will, QoS 0 and 1, and a reconnect with bounded backoff. The other half of cancho-mqtt.

Recorded, not staged

See it refuse, then run.

Real terminals, real output; only the typing is simulated. A leaked file is refused by a named rule, one line fixes it, and the compiler says what the program may do. Then the same idea, lifted to a UI.

Deliberately not here

What was left out is the design.

garbage collectordestructorsexceptionsborrow checker implicit conversionsambient authoritytextual macrosproc macros

Borrowing is lexical: a region is a block, so a reference’s validity is read off the syntax. Io {} does not compile. Macros would break stable, content-addressable identity. The docs have the reasons.

Status: pre-1.0

  • Alpha and early products are built with it (see the map), each with an authority report the compiler derives. Alpha means it runs and may change.
  • The compiler is still the Rust one. The cancho compiler builds real programs but does not yet refuse everything the language refuses, so it is not the default.
  • Dependencies resolve end to end, and a real TLS handshake compiles and runs.
  • There is no manifest-level version string: a hash is what you depend on.
  • Claims that turn out wrong are corrected in place in the docs, not quietly edited.

The name

A big rock.

cancho is Spanish for a boulder. In La Pedriza, a granite landscape north of Madrid, weathered, jointed rock left fields of boulders resting on one another with nothing between them. Each stays by its own weight and what it touches. The language is built the same way: every piece says what it rests on, and the compiler checks it.
