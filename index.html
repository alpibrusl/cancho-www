Design stage · not a usable language yet

Ownership and authority, in the type.

A native systems language where a value is consumed exactly once, and reaching the outside world (the console, a file, a foreign library) requires holding a capability for it. Checked at compile time.

See an exampleRead the docs
$ cancho authority examples/tally.cho --std
performs
    io_read
    io_write
never touches
    the filesystem
    the heap
    the command line
    foreign code

$ cancho authority … --output json
{"bounded": false, "unbounded_by": ["scope:symbol", …]}
# fails closed when foreign code is reachable

Authority is a value

split(world) is the only place a program gets authority from. A function nothing was handed cannot print, however much it wants to.

Linear by default

An unused capability is still a linear value: forgetting to release one does not compile.

Content-addressed

A canonical AST gives every declaration a stable hash. Dependencies pin to hashes, not version strings.

Why a language of its own

Agents now write most of the code, and they pull in dependencies faster than anyone can read them. cancho is a bet that the answer is to own the stack (language, compiler, std, packages) and make what code may do a property of its type, so trust is checked by the compiler instead of assumed.

Owned, not borrowed

Dependencies are pinned to content hashes. Nothing changes under you because a maintainer published a new version.

Bounded, not trusted

Foreign code is allowed, but never hidden: cancho authority names exactly what is reachable, and says "unbounded" when it can't bound it.

Agent-first tooling

Diagnostics, the command tree and a SKILL.md all come out of the binary as data. See AGENTS.md.

It is a bet, not a result: cancho is at design stage, and owning everything only pays if agents make maintaining it cheap.

An example

greet says [io_write] because it was handed a borrowed capability. main's row is [] even though it prints, because it owns the capability rather than borrowing one.

import std.io;

fn greet[&i, &r](io: &!i Io, name: &r [byte]) -> [io_write] int {
    io.write_all(io, "Hello, ");
    return io.write_all(io, name);
}

fn main(world: World) -> [] int {
    let Split { io, ffi, fs, heap, args } = split(world);
    release(ffi); release(fs); release(heap); release(args);

    borrow mut io as &!i in {
        greet(i, "cancho");
    }
    release(io);
    return 0;
}

Syntax at a glance

Familiar on the surface: let, fn, struct, enum, match. The signature carries what's unusual: an effect row between -> and the return type, and a mode on every type. All snippets are from examples/tour.cho and the compiler's reject tests.

Data and exhaustive match

struct Vec2 {
    x: int,
    y: int,
}

enum Shape {
    Empty,
    Circle(int),
    Rect(int, int),
}

fn area(s: Shape) -> [] int {
    match s {
        Shape::Empty => { return 0; }
        Shape::Circle(r) => { return 3 * r * r; }
        Shape::Rect(w, h) => { return w * h; }
    }
}

[] means pure. match must cover every variant, and the compiler names the ones you forgot.

Generics

enum Opt[T] {
    None,
    Some(T),
}

fn unwrap_or[T: val](o: Opt[T], fallback: T) -> [] T {
    match o {
        Opt::None => { return fallback; }
        Opt::Some(value) => { return value; }
    }
}

One definition, monomorphised per type it is used at. val is the unrestricted mode: copyable and discardable.

Linear resources

res struct Ticket {
    serial: int,
}

fn issue(serial: int) -> [] Ticket {
    return Ticket { serial: serial };
}

fn redeem(t: Ticket) -> [] int {
    let Ticket { serial } = t;
    return serial;
}

res is linear: exactly one use, no implicit copy, no implicit discard. There are no destructors; a resource is spent by taking it apart.

What the compiler refuses

fn disagree(f: Ticket, flag: bool) -> [] int {
    if flag {
        let fd = close(f);
    }
    return 0;
}
$ cancho check branches_disagree.cho
branches_disagree.cho:19:5: error: the branches disagree about `f`:
one consumes it and another does not
        if flag {
        ^^^^^^^^^

Only one branch consumes f. Rust would insert a hidden runtime drop flag; cancho refuses instead.

Effect rows are exact and transitive: declaring an effect you don't perform is as much an error as performing one you didn't declare. The full language is in the docs.

What's deliberately not here

No garbage collector, destructors or exceptions

A resource is destroyed by naming the function that knows how.

No borrow checker

Borrowing is lexical: a region is a block, so validity is read off the syntax.

No implicit anything

No implicit conversions, no ambient authority. Io {} does not compile.

No textual or proc macros

They break stable, content-addressable identity.

Services and tools

cancho-hooks Alpha

Webhook delivery: on disk before the 202, signed, retried, replayable. Not for production yet.

cancho-cache Alpha

Redis-compatible string cache over RESP2/RESP3 in a fixed arena. 38 of Redis 7.0’s commands.

cancho-tools Working

Nine command-line tools for agents: seek, list, peek, jsonq, tally, hash, write, replace, move.

Libraries

cd cancho
cargo test --workspace   # the whole gate: fmt, clippy, every test

Green on linux-x86_64 and darwin-aarch64. Codegen is LLVM via clang by default; --backend cranelift is faster to iterate on.

Status: design stage

  • Dependencies resolve end to end, and a real TLS handshake compiles and runs.
  • There is no manifest-level version string: a hash is what you depend on.
  • Claims that turn out wrong are corrected in place in the docs, not quietly edited.
