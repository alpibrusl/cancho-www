Trust without comprehension

Pre-1.0 · alpha products are built with it

Tools built for agents.
Not adapted from humans.

cancho is a programming language and toolchain for software built by AI agents and checked by machines. Programs declare what they can do, dependencies have stable identities, and the compiler returns structured evidence that other tools can read and check.

The bet: you should not have to read what an agent wrote to trust it.

Comprehension was a strategy. It is not the only one. Trust Without Comprehension

Identity, not lines

A canonical AST gives every declaration a stable hash, and dependencies pin to hashes, not version strings. Nothing changes under you because a maintainer published a new version.

Authority, not trust

What a program may do is in its type, so a reviewer checks the policy, not every line. cancho authority names what is reachable, and says “unbounded” when it can’t.

Verified, not read

The compiler answers in data: a rule tag, a position, a fix. Diagnostics, the command tree and a skill file come out of the binary for an agent to use directly.

Evidence, with its limits

What cancho verifies today.

Three lists, kept apart: what the compiler refuses, what tests exercise, and what is still being established. Every line links the document, fixture or issue behind it.

Verified by the compiler

  • A value is consumed exactly once. A resource left unconsumed is refused as linear-value-unconsumed (19 refusal fixtures). rule fixtures
  • Effect rows are exact. Performing an effect the signature does not declare is refused as effect-not-declared (12 fixtures); declaring one that is not performed is refused too. rule fixtures authority
  • Authority is derived, not declared: cancho authority lists what a program can reach, and says “unbounded” when foreign code is reachable. authority foreign code
  • Every refusal carries a stable rule tag, and --output json gives it as data. the contract
  • Each declaration has a content hash (cancho ids); dependencies pin to hashes. canonical AST (status: proposed)

Exercised by tests

  • 359 refusal fixtures, each naming the rule it must be refused with, and 123 accepting programs. tests/reject tests/accept
  • The conformance suite builds and runs real programs; the gate (format, clippy, tests) runs on linux-x86_64 and darwin-aarch64. CONTRIBUTING
  • Every checked code block in AGENTS.md is a fixture; changing a rule name to a wrong one turns the suite red (checked by doing it). AGENTS.md
  • A mutation fuzzer feeds token-level edits of every program through parsing, checking and code generation, requiring no panic, a stable print-and-parse, and that what the checker accepts the backend compiles. fuzzer design
  • Tests are checked by breaking what they cover and watching them fail. CONTRIBUTING differential testing
  • With every build going through the compiler written in cancho, 697 of 704 conformance tests pass (measured 2026-10-15, macOS aarch64). bootstrap record

Still being established

  • The compiler written in cancho refuses 256 of the 333 programs that must be refused, with the same rule as the Rust one. It is not the default. epic #491
  • Hash stability is not a contract yet: the canonical-AST document is “proposed”, and 39% of this repository’s own historical revisions do not type-check under today’s build. canonical AST hash stability
  • A cancho program has one network bound shared by listening and connecting, so a proxy’s authority report cannot say which upstreams it reaches; cancho-gateway enforces its compiled-in list by exact match and tests it, but the compiler does not vouch for it. cancho-gateway
  • The TLS stack is not independently reviewed (stated in cancho-fetch’s README). cancho-fetch
  • Not evaluated: whether agents do better with cancho-tools than with the usual tools. That needs an agent-in-the-loop evaluation that has not been run. cancho#228
  • Pre-1.0, supported on linux-x86_64 and darwin-aarch64 only, and its own README says it is not a usable language yet. README

A passing check shows that the checks listed here passed. It does not show a program is correct or secure in every respect, and tests exercise the behaviour they cover, not all behaviour. None of this is a certification, and no independent audit is claimed. Counted at cancho 1d4c44e, 2026-10-20. Each line links its evidence; a claim found false is corrected here, in place.

  • cancho-log (early): A durable, segmented, append-only log with crash-safe recovery that cuts off a torn tail.
  • cancho-stats · page (built): Statistics whose last digit you can check: a command line for describing data and drawing inferences, with exact sums and error bounds written before the code.
  • cancho-ml · page (alpha): Classical machine learning on tabular data as a command line an agent can read: seven models, one JSON line out, or a named refusal with a repair.

  • cancho-robot · page (design): A robot arm controller: the Feetech servo bus, SO-101 kinematics and a safety core every motion goes through.
  • cancho-gpu · page (built): A compiler for typed tile kernels (.chx) to CUDA C and Metal, written in cancho; it also runs language models on a Metal GPU.
  • cancho-code · page (built): An AI coding assistant that proves its work: the cancho compiler checks every piece the model writes, and a task is done only when the compiler and the task's own examples say so.

# A program that opens a file.
$ cat leak.cho
// Open a file.
import std.io;

fn main(world: World) -> [] int {
    let Split { io, ffi, fs, heap, args } = split(world);
    release(args);
    release(ffi);
    release(heap);
    var status = 1;
    let tmp = narrow(fs, "/tmp");
    borrow tmp as &c in {
        match open_read(c, "/tmp/notes.txt") {
            Opened::Ok(f) => {
                status = 0;
            }
            Opened::Failed(e) => {
            }
        }
    }
    release(tmp);
    borrow mut io as &!i in {
        if status == 0 {
            io.write_all(i, "opened it, closed it\n");
        } else {
            io.write_all(i, "no such file\n");
        }
    }
    release(io);
    return status;
}

Deliberately not here

What was left out is the design.

garbage collectordestructorsexceptionsborrow checker implicit conversionsambient authoritytextual macrosproc macros

Borrowing is lexical: a region is a block, so a reference’s validity is read off the syntax. Io {} does not compile. Macros would break stable, content-addressable identity. The docs have the reasons.

Status: pre-1.0

  • Alpha and early products are built with it (see the map), each with an authority report the compiler derives. Alpha means it runs and may change.
  • The compiler is still the Rust one. The cancho compiler builds real programs but does not yet refuse everything the language refuses, so it is not the default.
  • Dependencies resolve end to end, and a real TLS handshake compiles and runs.
  • There is no manifest-level version string: a hash is what you depend on.
  • Claims that turn out wrong are corrected in place in the docs, not quietly edited.

The name

A big rock.

cancho is Spanish for a boulder. In La Pedriza, a granite landscape north of Madrid, weathered, jointed rock left fields of boulders resting on one another with nothing between them. Each stays by its own weight and what it touches. The language is built the same way: every piece says what it rests on, and the compiler checks it.
